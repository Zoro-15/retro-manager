THE FORGE

Three taps from cartridge to launcher.

A 3-step Material 3 stepper with dark cards, a floating dock and a live terminal sheet. No command line. No desktop toolchain. Just your phone, your ROM, and 15 verified stages of engineering.

01

Select your ROM

Pick any legally-owned .gb, .gbc, .gba, .smc, .md, .nes, .z64, .pbp, .nds, .cue or arcade set. Headers are parsed at byte level — Nintendo logo validated, MBC detected, checksums streamed CRC32 / MD5 / SHA-1 / SHA-256 in a single zero-heap pass.

  • IPS / UPS patches on-the-fly
  • Archive auto-extraction
  • Multi-disc detection
02

Forge its identity

Name your game. Boxart is auto-scraped from the open-source Libretro Thumbnails library and composed into adaptive launcher icons. Choose touch layout, shader, bezel and controller mapping — all written into retropack.json inside the package.

  • Adaptive icon live preview
  • Deterministic package name
  • Per-console touch layouts
03

Install a real app

The template is mutated, aligned and cryptographically signed on-device — v1 + v2 + v3 in a single pass — then installed through the system package installer. It launches from your launcher, keeps its own saves, and updates in place without losing progress.

  • In-place versionCode bump
  • Self-contained APK output
  • Zero dynamic code loading

The toolchain, verbatim

  • ARSCLibStructured AXML mutation — string pools re-indexed, label inlined.
  • zipflinger16 KB page alignment padding for uncompressed .so libraries.
  • apksigv1 + v2 + v3 signatures applied in a single pass, then re-verified.
  • HybridKeystoreAES-256-GCM at rest, RSA/EC keys, PKCS#12 export. Device-bound.

Trust anchors

The generic template APK ships with bytecode SHA-256 trust anchors. After every mutation, protected entries — classes.dex and lib/arm64-v8a/*.so — are re-hashed and asserted. If a single byte drifts, the build refuses to sign.

SEPARATION OF POWERS

Manager ≠ Runtime ≠ Template ≠ Signer.

Seven architectural layers with frozen boundaries. The Manager understands runtime capabilities, never implementation. The Runtime Host understands emulation contracts, never game titles. The generated APK understands nothing but itself.

L·01

The Manager

A Jetpack Compose Material 3 orchestrator. Talks to runtimes through declarative BuildRequest payloads and capability descriptors. Contains zero emulator-specific logic — adding a 17th platform is a registry entry, not a rewrite.

L·02

The Runtime Host

The generic template APK: fullscreen immersive GameActivity, atomic ROM staging with SHA-256 validation, POSIX mmap loading, GLES rendering, Oboe audio, and touch + HID input coordination. Knows nothing about which game it runs.

L·03

The Transformer

The 15-step engine: streaming asset injection, ARSCLib AXML mutation, icon layer replacement, zipflinger alignment and apksig signing — all pure-Java, all on-device, no compiler toolchain ever touches your phone.

L·04

The Signing Identity

A hybrid keystore with an AES-256-GCM-encrypted master key, software RSA/EC signing keys and PKCS#12 export. Device-bound by design — no embedded release keys, ever. Sideload-grade identity with real cryptographic provenance.
